# Resume Audit

Drop this file in your job search folder, connect that folder in Cowork, and say: **"Read the Resume Audit file and tailor my resume for [ROLE] at [COMPANY]. Here's the job post: [PASTE JOB POST]"**

Claude checks the fit, maps the post to your proof, swaps in your best bullets, fits it to the page and runs the checks before anything goes out. The first time, it helps you fill in **My Resume Rules** at the bottom, so every resume after that follows the same rules.

Each step is tagged:
- 🤖 **Auto**: Claude does this for you
- 🙋 **You decide**: Claude asks, you answer

> **Golden rule:** The facts don't move. Claude chooses and orders your approved bullets, and nothing gets uploaded or sent without your OK.

---

## How Claude should use this file

You (Claude) are tailoring the user's resume to one job post. This file is your operating spec.

1. **Read this whole file first, every time,** especially My Resume Rules at the bottom. The written rules outrank anything you remember.
2. **If My Resume Rules is empty,** help the user fill it in before you tailor anything.
3. **Do the steps in order.** Stop after Step 2 if the role isn't a fit. Stop any time you need facts only the user can give.
4. **Never upload, submit or send anything.** Show the user the PDF and wait.

---

## Step 1: Gather everything 🤖

- Save the full job post word for word in the company folder, because postings come down.
- Read My Resume Rules and the bullet bank before touching anything.
- Use the standard resume .docx as the base unless the user says otherwise. Check it's the right file by its size and date, not its name.
- Ask what the recruiter said they want, if anything. One line from a recruiter can change which bullets lead.
- If there's an application form, check what it asks before drafting.
- Tell the user what you've got and what you still need. Don't edit yet.

## Step 2: Check the fit 🙋

- Check the must-haves against the user's real background. Years can flex by about a year.
- If the core of the role is a domain or stack that isn't anywhere on the resume, say so and suggest skipping it.
- Say whether the standard resume is good enough or tailoring gives a real edge, and why. The user decides.

## Step 3: Map the post to proof 🤖

- Quote every must-have and nice-to-have word for word, with the bullet or tag that proves it next to each one.
- Mark the gaps. Don't fill them, and don't add any line that admits what the user hasn't done.
- Flag gaps that might be work the user did but never wrote down. Those are questions for the user, not guesses.
- Flag it if the base leans the wrong way for this post.

## Step 4: Mirror the true keywords 🤖

- Pull the exact title, the phrases in the must-haves and every tool named.
- Mirror them only where they're true, in 4 places:
  1. The first summary label
  2. The summary nouns
  3. The skills lines
  4. The nouns inside a bullet
- If a phrase would sound weird said out loud across a table, leave it out.
- Fallback: list the words the post repeats with how many times each shows up, and check which ones are missing. The true ones go in the 4 places above.

## Step 5: Swap the bullets 🤖

- **Swap, don't rewrite.** Pick from the bullet bank and order them. The facts don't move.
- **Counts:** current role 4 to 5, earlier roles 2 to 3. Never 6, never a single-bullet role.
- **Order:** inside each role, the best match for this post goes first.
- **Bullets stay inside their own role.**
- **X-Y-Z:** outcome and number first, then how.
- **Two lines max,** no periods at the end, no I, me, my, we or our.
- **Strongest opening verb,** and no two bullets in a row with the same one, across roles too. Fix it by reordering, not rewording.
- **Nouns can change** to match the post's wording. Facts can't.
- **New bullets:** write them X-Y-Z from the story bank or the user's facts, mark them ★, add them to the bank, and show the user before they go on anything.
- **Summary:** only swap the two labels and the nouns. Leave the rest of each sentence exactly as it is.
- **Skills:** rebuild the categories around the post's wording.

## Step 6: Fit the page 🤖 then 🙋

- Export the PDF and check the page count. Don't guess.
- One page is the default. If it's two, page 2 only has skills and education.
- Cut the least relevant bullet from the bottom of a role. Never shrink the font below 10pt.
- No two bullets that tell the same result twice, and nothing without a number.
- If the only way to fit is choosing between two roles, show the user the options with the page result of each and let them pick.

## Step 7: Keep the titles 🙋

- Titles stay the same as LinkedIn and the standard resume. You can suggest a change and say why, but don't make it.
- Flag any internal or level title a recruiter wouldn't type into a search bar.
- Use the role exactly as posted in the file name: `Firstname Lastname - <Company> (<Role as posted>).pdf`

## Step 8: Format the page 🤖

- Follow the house style in My Resume Rules.
- For cold applications through a job board: single column, no tables, nothing in the header or footer.
- Check the PDF, not the doc.

## Step 9: Check, save and show 🤖 then 🙋

Run every check and tell the user which passed and which didn't:

1. Page count is right
2. No heading stranded at the bottom of a page
3. No em dashes, and en dashes only in date ranges
4. Numbers match the canonical numbers in My Resume Rules
5. Nothing from the Never write list
6. Every ★ bullet has the user's OK
7. No names from the Names I can't share list
8. No repeated opening verbs in a row, across roles too
9. No periods at the end, no first person, nothing over 2 lines
10. Summary unchanged except the labels and nouns

Then:
- Save the .docx and .pdf in the company folder, and move any older version to `version history/`
- Add new bullets to the bank and new facts to the story bank
- Show the user the PDF and **wait**. Don't upload or send anything until they say so

---

## The rules that keep it honest

- **The facts don't move.** Choose and order, don't invent.
- **No gaps on the page, and no lines admitting them.**
- **Never change a title** without the user saying so.
- **New bullets need the user's OK** before they go anywhere.
- **Never upload, submit or send.** The user does that.
